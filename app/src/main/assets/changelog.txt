1.1 (2026-11-21)
- 新增：搜索框里直接贴 http(s) 音频直链即可播放，不用插件、不消耗音源额度。
- 新增：本地音乐页右上角「服务器」按钮，支持 SMB / FTP / SFTP / WebDAV 连接文件服务器，按目录浏览并直接播放其中的音乐。
- 本地页「服务器」先自动搜索局域网里的 SMB 服务器（扫 445 端口 + mDNS + NetBIOS 名字），选中后只填账号密码；连过的服务器会被记住，再次选中直接登录，长按可重新配置。
- 新增：本地页搜索框，可按曲名/歌手/专辑过滤本地曲库。
- 文件浏览页：左上角返回按钮、进入子目录后可返回上级；目录显示文件夹图标；隐藏 SMB 的 C$ 等管理共享。
- 播放服务器上的文件时自动读取容器标签与音频规格（标题/歌手/专辑/封面、位深/采样率/声道/码率），列表仍只显示文件名、不额外请求。
- 服务器文件切歌到下一首时，播放页与迷你条会自动补上标签、封面与规格（读一次即缓存）。
- 播放页会读取文件里内嵌的歌词（FLAC 的 LYRICS/USLT/UNSYNCEDLYRICS、MP3 的 USLT 等），兼容老工具写入的 GBK 编码。
- 遥控器适配：可获得焦点的行/按钮都有焦点描边、页面进入自动落焦点、搜索结果里按「返回」先回到底部三个标签页；播放列表/均衡器/歌词搜索从底部弹层改成屏幕中央的窗口。
- 大屏（≥700dp）播放页改为封面在左、歌词在右同时显示，小屏仍是封面/歌词切换。
- 播放页底部四个按钮整体上移，避开电视过扫描被切边；「上一首/下一首」可用左右键从播放键直接选中。
- 电视（Android 5.1）上服务器音乐的标签/封面恢复正常：FFmpeg 库改用自有 soname，不再被固件自带的同名系统库抢占。
- 升级到 FFmpeg 9.0（libavformat / libavcodec 63），解码器与容器格式保持不变。
- 修复播放网络文件时内存不足崩溃（缓冲上限从 600 秒改为 90 秒 / 32 MiB 双上限）。
- 修复歌词偶尔跳回开头：同一首歌被元数据刷新触发重复加载时不再重建歌词视图。

应用正式发布 (2026-11-21)
- 版本号 1.0
- 正式包默认关闭详细调试日志：解码、USB 直通、插件的逐条诊断不再写入，需要排查时到「设置 → 通用 → 详细调试日志」打开
- 最低支持 Android 5.1（API 22），可装在老电视/老设备上

- 本地库标签兜底：新增 FFmpeg 标签读取（ffaudio.c 的 nativeTags），title/artist/album/albumArtist/date/track/disc/genre/comment/encoder + 内嵌封面；MediaMetadataRetriever 读不出内容的 .dsf/.wma/.aiff/.dts 现在能正确显示曲名、歌手、专辑与封面
- 诊断：DAC 音量探测的原始返回值（cn/min/max/res 或 STALL 码）写入"复制诊断日志"，硬件音量读不到时能直接看到失败原因
- 修复硬件音量永远探测失败：UAC2 没有 GET_MIN/GET_MAX/GET_RES，正确做法是用 RANGE(0x02) 一次取回 wNumSubRanges + (MIN,MAX,RES)；CUR 也应为 0x01（方向位区分读写），此前用的 0x81 只对 UAC1 成立
- 时钟采样率回读（GET_CUR）同样改用 UAC2 请求码，设置成功后不再回读为 null
- 直通定位改为"解码丢弃"（nativeSkipTo），不再调用 av_seek_frame：后者在真机上会卡住/落到数据块外，表现为从中间播放整首静音、界面像卡死
- URB 队列深度默认 16→32（约 256 ms），减少欠载导致的爆音
- 缓冲默认回到 512 KB（2048 KB 实测会卡顿，缓冲只影响延迟，不是越大越好）
- 直通：seek/切模式后可能整首静音（定位落到数据末尾被判成"播完"）已修，超长目标会夹回时长内、读空时回退到开头重试
- 直通：环形缓冲不再写死 512 KB，可在 DAC 面板里按 256/512/1024/2048/4096 KB 切换（越大越抗爆音）
- 直通：生产者节流阈值跟随真实缓冲容量（原来写死 1.4 MB，比容量还大，等于从不节流）
- 诊断：新增 seek 目标/时长、read 前 5 次、每 2 s 缓冲占用与欠载计数、urb sub/comp/err 日志
- 直通音量改走 DAC 硬件音量：UAC1/UAC2 都用 GET_MIN/GET_MAX/GET_RES（每样本 1/256 dB、有符号）探测 FEATURE_UNIT，音量条与音量键直接写设备寄存器；没有硬件音量的设备自动退回软件衰减，日志会打印 `硬件音量：…` / `软件衰减：… dB`
- 修 24bit DAC 一直显示"硬件音量不可用"：旧代码用 14 字节的 range 结构读音量（并非音量请求），改为逐通道探测并支持通道 0..N
- 本地库扫描支持 DSF/DFF、AIFF、WMA/ASF、DTS、MKA：白名单补齐，并对媒体库不收录的格式补扫 MediaStore.Files
- 本地曲目规格（位深/采样率/码率）在 MediaExtractor 读不出时改用 FFmpeg 容器信息兜底
- 许可合规：新增 LICENSES/LGPL-2.1.txt（并随 APK 放到 assets/licenses/）、docs/ffmpeg-build.md 与 docs/ffmpeg-configure-flags.txt，写明 FFmpeg 7.1 的 NDK 版本与全部 configure 选项；「第三方组件」页新增 FFmpeg 条目
- 接入 FFmpeg（libavformat/libavcodec/libswresample）：本地文件的位深/采样率由库读取，24bit 直接以 3 字节样本送 DAC，不再依赖 MediaExtractor 的矛盾字段
- 新增 native/ffaudio.c 与 audio/FfAudio.kt：本地文件（file/content）解码后按 DAC 的等时格式输出，网络曲目仍走系统解码
- 直通日志新增 `ffmpeg: src=…Hz/…ch/…bit`、`ffmpeg first write: … hex=…`
- 直通：每样本字节数改为优先信 extractor 的 bits-per-sample（24bit ⇒ 3 字节），文件头解析降为后备，修 24bit 被当 16bit 送导致的声音异常
- 诊断：日志新增 `源布局：bits=… ⇒ …B` 与 `文件头 hex: …`
- 直通：样本宽度改由「extractor 真读一帧 / 声道数」决定（不再依赖 WAV fmt 解析），修 24bit 文件被当成 2 字节样本导致的声音错乱
- 直通：新增 24bit 打包饱和，避免 float 溢出到被丢弃的第 4 字节
- 诊断：日志增加 `probe ... frame=` 与 `源布局：帧=…B/…ch ⇒ … 字节每样本`
